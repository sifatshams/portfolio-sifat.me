Personal portfolio website for **Sifat Bin Anwar**, Full Stack Web Developer. Built as a single **Next.js 16 (App Router)** application — the same project serves both the **frontend (client)** and the **backend (API routes)**, so there is no separate backend server/repo to run.

## 🧩 How it works — Client + Backend in one project

This project **does not have a separate backend folder**. Next.js App Router handles both sides inside the same codebase:

- **Client (Frontend)** → everything under `app/page.tsx`, `components/`, `hooks/`, `lib/` that renders the UI. It's a single-page portfolio made of stacked sections (Hero, About, Skills, Projects, Experience, Certificates, GitHub Stats, Contact).
- **Backend (Server)** → anything under `app/api/**/route.ts`. These are serverless API route handlers that run only on the server (Node runtime on Vercel), never shipped to the browser. Right now there is one backend endpoint: the **Contact API**.

So "client calls backend" simply means: a React component/hook on the page calls `axios_instance` → which hits `/api/...` → which is handled by a `route.ts` file in `app/api/...` → which may call an external service (Brevo) → and returns JSON back to the client.

  use-active-section.ts, use-mouse-position.ts, use-scroll-progress.ts
  contact/useSendContactMessage.ts  → React Query mutation hook that calls the Contact API

                            projects, experience, certificates) — edit this
                            file to update the portfolio content
  axios_instance.ts      → Axios client, baseURL from NEXT_PUBLIC_API_BASE_URL

  motion.ts, utils.ts     → Animation variants & utility helpers

  index.ts, contact.ts    → Shared TypeScript types

                             (X-Frame-Options, X-Content-Type-Options,
                             Referrer-Policy, Permissions-Policy) to every response

## 🌐 Routes

### Page routes (client)

| Route | Description |
|---|---|
| `/` | Single-page portfolio — all sections (`Hero`, `About`, `Skills`, `Projects`, `Experience`, `Certificates`, `GithubStats`, `Contact`) render on this page, navigated via in-page anchor links (`#home`, `#about`, `#skills`, `#projects`, `#experience`, `#certificates`, `#github`, `#contact`) |
| `/sitemap.xml` | Auto-generated by `app/sitemap.ts` |
| `/robots.txt` | Auto-generated by `app/robots.ts` |
| `/manifest.webmanifest` | Auto-generated by `app/manifest.ts` (PWA manifest) |
| `/resume.pdf` | Static resume served from `public/` |

### API routes (backend)

| Method | Route | Description |
|---|---|---|
| `POST` | `/api/contact` | Validates the contact form payload (`name`, `email`, `subject`, `message`) with Zod, builds an HTML email, and sends it via the Brevo API to `CONTACT_RECEIVER_EMAIL`. Returns `{ success, message }` (and field-level `errors` on validation failure). |

**Request body:**
```json
{
  "name": "John Doe",
  "email": "john@example.com",
  "subject": "Let's work together",
  "message": "Hi, I'd like to talk about a project..."
}
```

**Success response — `200`:**
```json
{ "success": true, "message": "Your message has been sent successfully!" }
```

**Validation error — `400`:**
```json
{ "success": false, "message": "Please provide valid contact information!", "errors": { "email": ["Please provide a valid email address."] } }
```

**Server error — `500`:**
```json
{ "success": false, "message": "Unable to send your message right now. Please try again later!" }
```

### External API (called from the client)

- `GET https://api.github.com/users/{githubHandle}` and `GET https://api.github.com/users/{githubHandle}/repos?per_page=100` are called directly from `components/sections/github-stats.tsx` (public GitHub REST API — no auth) to power the live GitHub stats section.

## 🔑 Environment Variables

Create a `.env.local` file in the project root (never commit this file — it's already git-ignored):

```env
# Brevo (transactional email) — used by the backend Contact API
BREVO_HOST=smtp-relay.brevo.com
BREVO_PORT=587
BREVO_SENDER=my-sender-email@example.com
BREVO_USER=my-brevo-smtp-user
BREVO_PASS=my-brevo-smtp-password
BREVO_API_KEY=my-brevo-api-key
CONTACT_RECEIVER_EMAIL=where-contact-messages-should-arrive@example.com

# Client — base URL the frontend uses to call the backend API routes
NEXT_PUBLIC_API_BASE_URL=http://localhost:3000/api
```

For production (e.g. on Vercel), set the same keys in **Project Settings → Environment Variables**, with:
```env
NEXT_PUBLIC_API_BASE_URL=https://sifat-me.vercel.app/api
```

> ⚠️ **Security note:** `BREVO_API_KEY` / `BREVO_PASS` grant email-sending access. Keep them only in `.env.local` / your hosting provider's environment settings — never commit them to Git or share them publicly.

## 🚀 Getting Started

```bash
# 1. Install dependencies
npm install

# 2. Add environment variables (see above)
cp .env.local.example .env.local   # or create .env.local manually

# 3. Run the dev server (client + backend together)
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) — the same server handles both the UI and the `/api/*` backend routes.

## ☁️ Deployment (Vercel)

This project is deployed on **Vercel**, which builds and hosts both the client and the backend API routes automatically — no separate backend deployment is needed:

1. Push the repository to GitHub.
2. Import the repo into Vercel.
3. Add the environment variables listed above in Vercel's project settings.
4. Vercel runs `npm run build` and deploys — `app/api/**` routes are deployed as serverless functions automatically.

Live: **https://sifat-me.vercel.app/**

## ✏️ Editing Content

All portfolio content (name, role, links, skills, projects, experience, certificates, stats) lives in **`lib/data.ts`** — update that single file to change what appears on the site. The résumé PDF is served from `public/sifat-official-resume.pdf` at the `/resume.pdf` route, and the GitHub Stats section pulls live data from the public GitHub API for the handle configured in `lib/data.ts`.

## 📝 Notes

- The custom cursor / cursor-follower effects auto-disable on touch devices.
- `prefers-reduced-motion` is respected site-wide.
- Security headers (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`) are applied globally via `proxy.ts` middleware.
- Update `siteUrl` in `app/layout.tsx`, `app/sitemap.ts`, and `app/robots.ts` if the production domain changes.
